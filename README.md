# 여행 일정표 (trip)

떠나기 전에 미리 짜 두고, **현지에서 그때그때 고친다.** 장소는 구글맵 링크를 붙여넣으면
알아서 채워지고, 하루치가 지도 위에 선으로 이어진다. 비용은 그 줄에 같이 적고,
동행자와 같은 표를 본다. **빌드 스텝 없는 정적 웹앱**이다.

- **라이브:** https://thpht-trip.vercel.app
- `index.html` + `css/app.css` + `js/`의 클래식 스크립트. 번들러·빌드 없음.

> ⚠️ 이 앱은 **자기가 속한 여행만** 보여준다. 신규 가입이 열려 있으므로(동행자 때문에)
> RLS 가 유일한 방어선이다 — 표를 더할 때 `using` 과 `with check` 를 둘 다 거는 것을 잊지 말 것.

---

## 무엇을 만드나

**여행이 그릇이고 그 안에 날짜별 일정이 쌓인다.** 트리플과 같은 구조다.
다만 트리플이 "추천받아 담는 것"에 무게를 둔다면, 이건 **내가 이미 정한 것을 적어 두는 표**다.

중요한 것은 **과거와 미래가 한 표에 있다**는 점이다. 두 달 전에 숙소를 넣고, 현지에서
"여기 괜찮네" 하고 한 줄 추가하고, 돌아와서 비용을 채운다. 셋이 같은 화면 같은 표에서
일어난다. 이게 "기록 앱"과 "일정 앱"을 가르는 지점이고, **설계의 거의 전부가 여기서 나온다**
— 그래서 `items` 의 거의 모든 칸이 nullable 이다. '아직 안 정했다' 가 정상 상태이기 때문이다.

**사진은 다루지 않는다.** 그 결정 하나로 Supabase Storage 와 업로드 실패·용량·비용·리사이즈가
통째로 빠졌고, 앞선 두 프로젝트(card-dashboard·stock)의 "텍스트만 저장한다" 원칙이 유지된다.

## 트리플에서 가져온 것과 안 가져온 것

트리플의 일정표는 **Day1~DayN 구획**, 항목마다 **순번·시각·장소명·카테고리**,
**장소와 장소 사이의 거리 표기**(누르면 길찾기), 하단 **Day 탭**, 가계부의 **"누가 결제했나"**,
**체크리스트**, **초대 링크**로 이루어져 있다.

| 가져온다 | 안 가져온다 |
|---|---|
| Day 번호 + 요일 (`Day 3 · 2.22/목`) | AI 자동 일정 생성 · 장소 추천 |
| 그날 안의 순번 | 평점 · 리뷰 · 사진 |
| **장소 사이 거리 표기** | 항공 · 호텔 예약 |
| 하단 Day 탭 | 이동시간 고려한 자동 동선 정렬 |
| 가계부의 "누가 냈나" | |
| 체크리스트 · 초대 링크 | |

안 가져오는 것들은 전부 **여행 콘텐츠 DB 나 유료 경로 API 가 있어야** 성립한다.
트리플의 본체가 사실 그 DB고, 우리에겐 없다.

> **트리플은 "어디 갈지 정하는 것"을 돕고, 이건 "정한 것을 들고 다니는 것"을 돕는다.**
> 그래서 추천은 없지만 오프라인에서 열리고, 예약번호가 있고, 링크 하나로 장소가 채워진다.

## 구글맵을 링크로 다룬다

이 앱에서 가장 값진 결정이다. **구글맵 JS API 를 붙이지 않는다.** 대신 공유 링크를 파싱한다.
그것만으로 **Google Cloud 결제 계정 · API 키 관리 · Places 호출 비용 · `connect-src` 개방 ·
CDN 스크립트 의존**이 전부 사라진다.

```
https://www.google.com/maps/place/에펠탑/@48.8583,2.2919,17z/data=!3m1!4b1!4m6
!3m5!1s0x47e66e2964e34e2d:0x8ddca9ee380ef7e0!8m2!3d48.8583701!4d2.2944813

  /place/…      장소명 (URL 인코딩)
  @lat,lng      ★지도 중심이다. 핀 위치가 아니다 — 쓰면 수백 미터 어긋난다
  !1s0x…:0x…    구글 place id
  !3d / !4d     ★진짜 핀 좌표. 이걸 쓴다
```

**단축 링크만 서버가 필요하다.** 폰에서 공유하면 `maps.app.goo.gl/AbCd…` 가 나오는데
리다이렉트를 따라가야 하고 브라우저에서는 CORS 에 막힌다. stock 의 `api/naver.js` 와
완전히 같은 상황이고 해법도 같다 — 서버리스 프록시가 대신 따라간다.

```
GET /api/gmaps?u=https://maps.app.goo.gl/AbCd1234
  → { name: "에펠탑", lat: 48.8583701, lng: 2.2944813,
      url: "https://www.google.com/maps/place/..." }
```

- **호스트 허용목록이 필수다.** 안 하면 내 도메인이 아무 데나 요청을 던지는 SSRF 통로가 된다.
- **로그인 확인**도 `api/naver.js` 방식 그대로. 실패하면 통과시키지 않는다(fail closed).
- **전체 URL 을 붙여넣었으면 서버를 안 부른다** — 브라우저에서 바로 파싱한다.

> ⚠️ 공식 API 가 아니라 **URL 형식에 기댄 파싱**이다. 구글이 형식을 바꾸면 깨진다.
> 그때는 **장소명을 손으로 적게 두고 링크는 그대로 저장한다** — 자동 채움은 편의지 필수 경로가 아니다.

### 거리 표기와 길찾기는 공짜로 얻는다

좌표를 이미 갖고 있으므로 두 지점 사이 **직선거리는 하버사인으로 그 자리에서** 나오고,
길찾기는 URL 을 만들어 넘기면 된다. 호출도 키도 없다.

```
https://www.google.com/maps/dir/?api=1&origin=35.6586,139.7454&destination=35.7101,139.8107
```

표시는 **"직선 4.2km"** 처럼 직선임을 밝힌다. 트리플은 경로 기준이라 값이 다르다 — 숨기지 않는다.

## 지도 — 마커와 하루치 동선

**MapLibre GL + MapTiler 벡터 타일.** 둘 다 `js/vendor/` 에 커밋한다 —
`supabase-js` 와 같은 방식이라 `script-src` 를 열지 않는다.

- **마커** — 좌표가 있는 일정마다. 번호는 그날 순서, 색은 장소구분. 이름표는 **늘 켜 둔다**
  (핀만 있으면 "1번이 어디였더라" 를 보러 일정 탭으로 돌아가게 된다).
- **동선** — **같은 날 안에서만** 잇는다. 3일차 저녁과 4일차 아침을 이으면 자정에 이동한 것처럼 읽힌다.
- **날짜 고르기** — 하루만 보는 것이 기본. 전체를 겹치면 도시 하나에서 실타래가 된다.
- **좌표 없는 일정** — 지도에 없다. 그 사실을 아래 한 줄로 적는다("좌표 없는 일정 3").
  조용히 빠지면 동선이 틀린 줄 모른다.

### 왜 래스터를 버리고 벡터로 갔나 — **글자 하나 때문이다**

처음엔 Leaflet 에 MapTiler 래스터 타일을 깔았다. 그런데 오사카를 열면 지명이 전부
`難波五丁目`·`日本橋` 로 나온다. 래스터는 **글자가 이미 타일 그림에 구워져** 나오기 때문에
`language` 파라미터가 통하지 않는다 — 붙이든 말든 응답 바이트가 동일하다(2026-09-01 실측).

벡터는 글자를 브라우저가 직접 그린다. 그래서 스타일의 `text-field` 를 바꿔칠 수 있다.

| | Leaflet + 래스터 | MapLibre + 벡터 |
|---|---|---|
| 라벨 언어 | 타일에 고정 | **바꿀 수 있다** |
| 지도 코드 | 43KB gz | 242KB gz |
| 요구 사항 | 없음 | WebGL |

### 한국어 라벨 — **먼저 세어 보고 정했다**

오사카 도심 z14 벡터 타일을 직접 뜯어 세었다(2026-09-01):

    이름 있는 지물 754개 · name:ko 55개(7%) · name:en 493개(65%)

국가·도시 줌에서는 `name:ko` 가 거의 100% 라 넓게 보면 전부 한글이지만
**골목까지 내려가면 한글은 7%뿐이다.** 그래서 폴백을 한 칸 더 둔다:

```js
['coalesce', ['get','name:ko'], ['get','name:en'], ['get','name']]
```

영어를 안 끼우면 골목이 통째로 일본어가 되고, 끼우면 그 자리가 `Nanba` 처럼 읽히는 로마자가 된다.
치환 절차는 MapTiler 가 자기 SDK 에서 하는 것과 같다(`maptiler-sdk-js/src/Map.ts`):
symbol 레이어의 `text-field` 만, **원본을 기억해 두고**, `{ref}`·`{number}` 는 건드리지 않는다.

CJK·한글 글리프는 서버에서 받지 않는다 — 다 받으면 수십 MB 다.
`localIdeographFontFamily` 로 **브라우저 글꼴이 그리게** 맡긴다.

### 밑그림은 MapTiler v4 스타일을 그대로 쓴다

    지도            streets-v4 / streets-v4-dark   (시스템 테마를 따른다)
    위성 + 길 이름   hybrid-v4
    위성            satellite-v4

기본은 **지도**다. 위성은 어디에 뭐가 있는지는 보여 주지만 뭐가 뭔지는 못 읽는다 —
일정을 훑는 화면에서는 지명과 도로가 먼저다. 위성은 단추 하나 거리고 고른 것은 기억한다.

CSS 필터는 걸지 않는다. 전에 OSM 을 회색조로 누르고 어두운 테마에서 반전까지 했는데,
반전은 건물을 검은 덩어리로 만들고 도로를 하얗게 튀게 해서 **원본보다 나빴다**.
MapTiler 가 테마마다 제대로 만든 스타일을 주므로 손볼 것이 없다.

> ⚠️ **상태코드만 보고 넘긴 확인이 두 번 사고를 냈다**(2026-09-01).
> ① CARTO Positron — `curl` 은 200 인데 타일에 `API KEY REQUIRED` 워터마크가 박혀 나왔다.
> ② MapTiler `Invalid key` — 우리 `Referrer-Policy: same-origin` 이 Referer 를 지워서였는데,
>    `curl` 로는 헤더를 손으로 넣어 200 이 왔다.
> **지도는 눈으로 봐야 한다.**

> ⚠️ **`map.isStyleLoaded()` 를 조건으로 쓰지 말 것.** MapTiler 스타일에는 저작자 표시만
> 담은 `maptiler_attribution` 소스가 있는데 `url` 도 `tiles` 도 없어 **영원히 로드되지 않는다.**
> 그래서 이 함수는 항상 `false` 다 — 여기에 동선 선 그리기를 걸었다가 선이 한 번도
> 안 나왔다. 준비 여부는 `style.load` 로 직접 센다.

- **저작자 표시는 ODbL 의무다**: `© OpenStreetMap contributors`. 지우지 말 것.
- 국내 POI 이름이 성긴 것은 **여기서는 덜 아프다** — 장소 이름은 이미 구글 링크에서 받아 왔고,
  지도는 "여기가 어디쯤인가"만 보여주면 된다.

## 데이터 모델

뼈대 — **여행구분 · 날짜일시 · 장소구분 · 장소명 · 구글맵링크 · 비용** — 그대로다.
**지출을 별도 표로 빼지 않고 일정 한 줄에 담는 것**이 이 모델의 핵심이다(트리플 가계부도
결국 일정에 붙어 있다). 여기에 공유용 `trip_members` 가 붙어 표 셋이다.
(준비물 `checklist` 표는 남아 있지만 2026-09-03 에 화면을 걷었다 — 쓰지 않아서다.)

| 표 | 담는 것 |
|---|---|
| `trips` | 이름 · 기간 · 기준통화 · 초대코드 · 소유자 |
| `items` | 날짜 · 시각 · 순번 · 장소구분 · 장소명 · 구글맵링크 · 좌표 · 비용 · 통화 · 환율 · 낸 사람 · 예약번호 · 예약링크 · 못감 · 메모 |
| `trip_members` | 어느 여행에 누가 · 역할 |

### 판단 몇 가지

- **시각은 없어도 된다.** 미리 짤 때 "3일차 점심"까지만 정하는 경우가 훨씬 많다.
  `at_time` 을 nullable 로 두고 `seq` 로 그날 안 순서를 잡는다. 시각이 있으면 시각이 이긴다.
- **비용도 없어도 된다.** 계획 단계에선 비어 있고 다녀와서 채워진다. 합계는 채워진 것만 더한다.
- **링크는 원문 그대로 남긴다.** 파싱이 틀렸을 때 되돌릴 근거가 그것뿐이고, 탭해서 여는 것도 원본이다.
- **환율은 원 자료를 남긴다.** stock 의 `cashflows` 와 같은 판단이다. `cost`·`cost_cur`·`fx`
  셋을 다 저장해야 "그때 환율"과 "오늘 환율"을 나중에 둘 다 낼 수 있다.
- **좌표는 둘 다 있거나 둘 다 없다**(`items_geo_chk`). 하나만 있으면 지도에 못 찍는데 있는 척하게 된다.
- **장소구분은 여섯이다** — 숙소 · 식사 · 관광 · 이동 · 쇼핑 · 기타. 늘리기는 쉽지만
  줄이기는 어렵다(이미 그 구분으로 적힌 줄이 생긴다). 좁게 시작한다.

### 안 담는 것

주소 · 전화번호(구글맵 링크가 대신한다 · 저장하면 낡는다) · 첨부파일(Storage 가 들어오는 순간
사진을 뺀 이유가 무너진다) · 이동수단 · 소요시간('이동' 일 때만 쓰는 칸이 둘 는다 — 메모로
충분한지 써 보고 정한다).

## 공유와 RLS — 여기가 제일 위험하다

앞선 두 프로젝트의 정책은 예외 없이 `user_id = auth.uid()` 한 줄이었다.
여기서는 **'내 것' 이 아니라 '내가 속한 여행의 것'** 을 읽어야 하고, 순진하게 바꾸면 터진다.

> ★★ `trips` 의 정책이 `trip_members` 를 조회하고 `trip_members` 의 정책이 다시 `trips` 를
> 조회하면 Postgres 가 정책을 재귀 평가하다 `infinite recursion detected in policy` 로 죽는다.
> **Supabase 에서 가장 흔한 사고다.**

끊는 방법은 `security definer` 함수다 — 함수 안의 조회는 RLS 를 지나가므로 재귀가 성립하지 않는다
(stock 의 `position_events.sql` 에서 이미 쓴 기법). 모든 표의 정책이 이 함수 하나만 부른다.

```sql
create function public.is_trip_member(t uuid) returns boolean
language sql security definer stable set search_path = public as $$
  select exists (select 1 from public.trip_members
                 where trip_id = t and user_id = auth.uid());
$$;
```

- **여행을 만들면 만든 사람이 자동으로 첫 멤버가 된다**(트리거). 안 하면 방금 만든 여행이
  자기 눈에도 안 보인다 — 정책이 멤버십으로 판정하기 때문이다.
- **초대는 `join_trip(code)` RPC 하나로만.** 클라이언트가 `trip_members` 에 직접 쓰는 길은
  열지 않는다(남의 여행에 자기를 밀어 넣을 수 있다).
- **여행을 고치고 지우는 것은 소유자만.** 동행자가 남의 여행을 지우면 곤란하다.

## 화면

앞선 두 앱은 한 단계짜리 탭 넷이었다. 여기는 여행을 고른 뒤에야 나머지가 의미를 가져 두 단계다.
대신 **진행 중이거나 곧 시작할 여행이 있으면 목록을 건너뛰고 바로 연다** — 현지에서 앱을 여는
이유가 그것이다.

| 경로 | 화면 | 내용 |
|---|---|---|
| `/` | 여행 목록 | 진행 중 · 예정 · 지난 것. 새 여행, 초대 링크로 참여 |
| `/t/<id>` | 일정 | Day 구획 · 순번 · 시각 · 구분 · 장소명 · 비용, 줄 사이에 직선거리. 하단 Day 탭 |
| `/t/<id>/map` | 지도 | 마커와 하루치 동선. 마커를 누르면 그 일정 줄로 |
| `/t/<id>/cost` | 비용 | 날짜별·구분별 합계, 기준통화 환산, 사람별 낸 돈 |
| `/t/<id>/info` | 여행정보 | 여행 설정(이름·통화·나라·도시·기간), 그 아래 동행자와 초대 링크 |

**추가는 한 칸에서 시작한다** — 구글맵 링크를 붙여넣는 칸 하나. 붙이면 장소명·좌표가 채워지고
날짜·구분·비용만 마저 고른다. 링크 없는 일정("10:30 인천공항 집합")은 장소명만 적어도 저장된다.

경로 라우팅은 stock 방식 그대로다(해시가 아니라 경로 — OAuth 리다이렉트 자리와 겹치지 않는다).
`vercel.json` 에 `/t/(.*)` → `/index.html` 리라이트가 필요하다.

## 오프라인

현지에서 데이터가 끊기는 것을 전제로 선을 긋는다. **일정은 이미 받아 둔 것이고, 적는 것은 끊겨도 된다.**

| 기능 | 오프라인 | 근거 |
|---|---|---|
| 일정 보기 | **된다** | 로컬 캐시. 현지에서 제일 많이 하는 일이다 |
| 일정 추가·수정 | **된다** | 아웃박스에 쌓고 연결되면 보낸다 |
| 비용 입력 | **된다** | 환율은 나중에 붙여도 원 자료가 남는다 |
| 예약번호 보기 | **된다** | 이게 되라고 저장하는 값이다 |
| 링크 자동 채움 | 안 된다 | 프록시가 필요 — 링크는 저장되고 이름은 나중에 |
| 지도 타일 | 안 된다 | 좌표 목록으로 물러난다 |

동기화는 card-dashboard 의 **그림자 대조 방식**(서버와 일치한다고 아는 상태를 들고 있다가
바뀐 행만 보낸다)에 **아웃박스 큐**를 얹는다. 공유 앱이라 **충돌 규칙**도 필요하다 —
v1 은 "나중에 도착한 쓰기가 이긴다", 지운 것은 되살리지 않는다.

## 원칙 — 무엇을 잇고 무엇을 깨나

| 그대로 잇는다 | 깬다 |
|---|---|
| 무빌드 · 클래식 스크립트 · 로드 순서가 곧 의존성 | **남의 데이터를 읽는다** — RLS 가 멤버십 판정으로 |
| CDN 의존 없음 (vendor 는 커밋) | **신규 가입을 연다** — 동행자 때문 |
| `connect-src` 는 자기 오리진 + Supabase + 타일 호스트 | (작게) 워커는 `blob:` 대신 파일로 (csp 빌드) |
| service_role 키를 쓰지 않는다 | |
| 비공식 소스는 섹션 단위로 degrade | |
| README 가 결정 기록 · 폰 우선 | |

**의도된 예외 하나:** "낡을 값은 저장하지 않는다" 를 지도에서는 어긴다. 좌표와 장소 이름은
저장한다(호출 비용과 오프라인 때문). 대신 영업시간·평점처럼 진짜 낡는 값은 담지 않는다.

## 더모아 계산기 — `/themore`

신한 더모아는 **5,000원 이상 결제의 1,000원 미만 잔돈**을 포인트로 준다(해외는 2배).
그래서 5,999원에 맞춰 긁는 것이 최적인데, 해외에서는 외화를 얼마 불러야 원화로 얼마가
찍히는지 알 수가 없다. 그 역산이 [themore.app](https://themore.app) 이 푸는 문제이고,
같은 셈을 `js/more.js` 에 옮겼다.

**여행에 딸린 것이 아니라 도구라 제 주소에 산다.** 비용 탭에는 찾아갈 링크 한 줄만 둔다 —
계산기는 특정 여행의 물건이 아니고, 결제 직전에 쓰는 것이라 여행 안까지 들어갈 이유가 없다.

### 환율을 어디서 얻나 — 여기가 이 기능의 전부다

| 필요한 값 | 어디서 | 누가 부르나 |
|---|---|---|
| 신한 1회차 USD/KRW 전신환매도율 | 신한은행 고시표 | **서버** (`api/more.js`) |
| 매매기준율 (이득률의 기준) | 같은 응답 | 서버 |
| 비자 통화→USD 환율 | 비자 고시환율 API | **브라우저** (`js/themore.js`) |

★★**둘로 나뉜 이유.** 비자는 데이터센터에서 부르면 Cloudflare 챌린지를 띄우지만
**CORS 는 열어 두어서 사람 브라우저는 그냥 읽힌다.** 반대로 신한은 서버에서 잘 되고
브라우저에서는 CORS 가 막는다. 그래서 각자 닿는 쪽에서 하나씩 가져온다.
2026-09-03 실측으로 17통화 전부 themore 가 보여주는 값과 소수점까지 같았다.

환율을 고르는 차례는 셋이다: **① 사람이 넣은 값 ② 비자 API ③ 신한 대미환산율 + 안전 여유.**
③은 비자에 못 닿을 때(비행기 안, 간헐적 실패)만 쓰는 그물이고, 화면이 지금 어느 것을
쓰는지 늘 적는다.

**★`api/fx.js` 로는 안 된다.** 저쪽은 네이버 **일별 종가**를 준다. 이 셈에 필요한 것은
그날 **1회차** 고시다. 2026-09-03 실측으로 신한 1회차 1,382.50 · 네이버 종가 1,373.70 —
0.64% 벌어진다. 5,999원에서 38원이면 999 경계를 그냥 넘어가므로, 종가로 계산하면
**틀린 금액을 알려 주는 계산기**가 된다.

**★처음에는 themore.app 의 API 를 프록시했다가 막혔다**(2026-09-03). 같은 회선에서
브라우저는 3ms 만에 200, 서버는 403 → 나중엔 응답 자체가 없었다. 데이터센터 필터가 아니라
**자기 페이지 밖에서는 안 쓰게 막아 둔 것**이다. 브라우저인 척해서 뚫지 않는다.
대신 신한은행이 제 고시표를 인증도 쿠키도 없이 열어 두고 있어서 **원천에서 직접** 받는다 —
값은 themore 가 주던 것과 세 날짜(평일·토요일·작년) 모두 정확히 같았다.

**★그물(③)이 필요한 이유.** 신한 **대미환산율**은 비자와 최대 0.35% 어긋나고 방향이 나쁘다 —
신한 쪽이 낮게 나와서 그대로 쓰면 999 를 **넘겨 버린다**. `MORE.SAFETY`(0.5%) 만큼 환율을
높게 잡아 항상 아래로 떨어뜨린다. 대가는 포인트 2,000 중 60~280. 달러는 비자가 바꿀
것이 없어(환율 1) 언제나 정확하다.

**★비자 API 의 함정 둘.** `amount=1` 로 물으면 IDR 처럼 단위가 작은 통화는 환산액이 0 으로
반올림돼 `{"status":"success"}` 만 온다 — 100 을 넣으면 나온다(환율은 금액과 무관).
그리고 `fromCurr`·`toCurr` 이름이 뒤집혀 있어서, '1엔이 몇 달러인가' 는
`fromCurr=USD&toCurr=JPY` 로 물어야 한다.

**★소수점 자릿수는 themore 와 일부러 다르다.** 저쪽은 ISO 4217 을 따라 TWD·IDR 을 두 자리로
두지만, 대만 단말은 NT$136.31 을 못 받고 루피아는 소수를 쓰지 않는다. 못 내는 금액을
알려 주는 것보다 낫다고 보고 그 둘만 정수로 끊는다(TWD 는 그 대가로 포인트 최대 86 손해).

### 여기만 로그인이 없다

`/themore` 와 `/api/more` 는 **로그인을 요구하지 않는다.** 앱의 나머지(일정·비용·`api/fx`·
`api/gmaps`)와 다른 예외이고, 이유는 셋이다: 오가는 것이 **공개 고시환율뿐**이라 지킬
개인 정보가 없고, 서버가 날짜별로 붙들고 있어서 **누가 몇 번을 부르든 신한에는 하루 한두
번**만 나가며, 그 덕에 폰에서 주소만 치면 바로 열린다. 남는 위험은 우리 함수를
낭비당하는 것뿐이라 **IP 별 분당 20회**와 `s-maxage`(가장자리 캐시)로 막는다.
페이지도 그만큼 가벼워졌다 — supabase 번들도 `db.js` 도 싣지 않고 요청 다섯 번에 뜬다.

### 검산

1. **신한 1회차 = themore 가 주던 값** — 2026-09-03 · 2026-08-29(토, 직전 영업일로 물러남) ·
   2025-01-15 세 날짜 모두 전신환매도·매매기준·고시시각까지 일치.
2. **비자 환율도 같다** — 17통화 전부, 소수점까지.
3. **셈이 같다** — 우리 `js/more.js` 를 **themore 페이지에 실어서** 그 자리에서 맞댔다.
   18통화 × 30줄, 저쪽의 환율·자릿수를 그대로 먹여 결제외화·청구금액이 전부 일치
   (IDR 만 다른데, 저쪽 해법이 창(窓) 탐색이라 최적을 못 찾은 것이다 —
   우리는 이분 탐색이라 같은 청구액에 **더 큰** 금액을 낸다).
4. **그물로 골라도 999 를 안 넘는다** — 통화 15개 × 목표 30줄 = 450줄을
   진짜 비자 환율로 다시 청구해 초과 0줄, 포인트는 최대치의 76~100%.

기대값은 **지어내지 않았다.** themore.app 화면에 뜬 숫자와 신한 응답 원문을
`tools/test-pure.js` 에 그대로 박아 뒀다. 한 번 기대값을 상상해서 적었다가 멀쩡한 코드를
틀렸다고 판정할 뻔했다.

**★버림이 세 번 들어간다**(비자 수수료 후 센트 버림 · 원화 환산 버림 · 서비스수수료 버림).
근사로는 안 맞아서 셈이 전부 정수다. 수수료를 소수로 뒀다가 `1.011 * 1000` 이 float 에서
1010.9999… 라 서른 줄 중 두 줄이 조용히 틀렸었다.

## 안 하기로 한 것

- **정산** (누가 누구에게 얼마) — 사람별 합계까지만 한다. 분담 규칙이 금방 불어난다:
  항목마다 참여자가 다르고, 1/n 이 아닌 분할이 있고, 선불·후불이 섞인다. 그것만으로 앱 하나다.
- **타일 사전 다운로드** — MapTiler 약관이 권하지 않고 구현이 무겁다.
- **실제 도로 경로** — 길찾기 API 가 유료다. 직선거리로 두고 그렇다고 적는다.
